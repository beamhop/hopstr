# Private DMs — NIP-17 gift wrap

Velvet's direct messages use **NIP-17 + NIP-59 gift wrap**: the message is sealed
with your key, then wrapped again with a *fresh ephemeral key per recipient*, with
back-dated timestamps. That hides not just the content but the metadata — who is
talking to whom, and when.

## The easy way (`@hopstr/agent`)

```ts twoslash
import { NostrClient, createIdentity } from '@hopstr/agent'
const nostr = new NostrClient(createIdentity())
const bob = createIdentity().npub
// ---cut---
await nostr.sendDM(bob, 'private hello')    // gift-wrapped to bob, with a copy to you
const convo = await nostr.readDMs(bob)      // [{ from, text, at }] — NIP-17 + legacy kind-4
```

The facade sends NIP-17 and also *reads* old kind-4 conversations, so nothing
disappears in the upgrade.

## Being discoverable — `bootstrap()`

A subtlety of NIP-17: before anyone can DM *you*, their client must discover where
to deliver the gift wrap. It reads your relay list (kind-10002), then looks there
for your **DM relay list** (kind-10050). If that kind-10050 is missing, clients like
iris show *"this user has not enabled encrypted messaging yet"* and refuse to send.

`bootstrap()` publishes everything a fresh identity needs to be found and messaged:

```ts twoslash
import { NostrClient, createIdentity } from '@hopstr/agent'
const nostr = new NostrClient(createIdentity())
// ---cut---
await nostr.bootstrap()
// kind-0     profile metadata        (placeholder name if you have none)
// kind-10002 relay list (NIP-65)     where your events live
// kind-10050 DM relay list (NIP-17)  where to deliver private messages
// kind-3     contact list (NIP-02)   seeds your social graph
```

It's idempotent: kind-0/kind-3 are only created when missing (never clobbering an
existing profile or follow list), and the routing lists are refreshed. The
`hopstr listen` daemon calls it automatically on connect, so a running daemon stays
DM-able. To publish just the kind-10002 + kind-10050 pair, use
`enableDirectMessages()`.

> Legacy kind-4 DMs are decrypted and printed inline by the daemon (via
> `decryptLegacyDM`); replies always go out as modern NIP-17.

## The explicit way (`@hopstr/nips/nip17`)

```ts twoslash
import { sealDirectMessage, openDirectMessage } from '@hopstr/nips/nip17'
import { createIdentity } from '@hopstr/core'
const me = createIdentity()
const bobPubkey = createIdentity().pubkey
const giftWrap = sealDirectMessage({ text: 'hi', to: [bobPubkey] }, me.secretKey)[0]!.wrap
// ---cut---
// one gift wrap per recipient PLUS one to yourself
const wraps = sealDirectMessage({ text: 'hey', to: [bobPubkey] }, me.secretKey)

// unwrap on the receiving side
const message = openDirectMessage(giftWrap, me.secretKey)
//    ^?
```

Under the hood the unwrap verifies the seal's signature and that the rumor author
matches it — a forged message is rejected, and a third party can't open your wrap.
